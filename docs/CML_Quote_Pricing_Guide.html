Functional overview

On configure, the constraint engine evaluates this CML before pricing procedures and Apex in the same Product Configure Business API call. It validates SKUs, enforces bundle and cross-sell logic, applies UOM/revenue defaults from Pricing_Type__c, and surfaces messages or hard errors to the configurator UI.

  1. User or integration adds or changes products on a quote; the configurator invokes CML with header context and PCM structure.
  2. Rules keyed to Token vs CPM vs Legacy paths set UOM/revenue preferences and block invalid combinations (dual standalone + bundle inclusion, Publicis-only SKUs, service package counts on Net New, and similar).
  3. Dependency require and informational message rules align: both must stay consistent when admins change a dependency.
  4. Values computed only in pricing (e.g. net unit price) are not visible to CML in the same pass — use configure → price → map externals → configure again when a rule must react to priced fields.

Performance: Large CML (~7k+ lines) affects quote load time. Monitor after changes; consider split/archive if the file grows past ~8,000 lines.

Pricing models

Token

  • Usage-based; UOM LiveRamp Tokens
  • Bundle-centric (LiveRamp Platform and Usage)
  • Revenue: Fixed or Revenue Share
  • Cannot sell the same product standalone and in the bundle on one quote

CPM

  • Cost-per-thousand impressions
  • Reach/frequency and impression-volume products
  • Default revenue: Fixed
  • Most lines: UOM = CPM

Legacy

  • Older agreements (often Clean Room)
  • More manual pricing and Premier Custom Services
  • Lower automation than Token/CPM paths

CML language reference (Salesforce core concepts)

Condensed from the Revenue Lifecycle Management Developer Guide — Product Configurator / CML. This section describes the language, not LiveRamp-specific rules. Official docs: cml_cml_core_concepts.htm and cml_core_concept_examples.htm on developer.salesforce.com.

CML supports // single-line and /* */ block comments.

Same-call limit: CML cannot read pricing- or Apex-computed values (e.g. NetUnitPrice) until a second configure pass after Pricing Business API

Global properties & settings

  • define CONST value; — global constant (numeric, string, regex). Example: define VOLTAGE_REGEX "^([0-9]+)/([0-9]+)$";
  • property maxRelationSize = n; — cap relation cardinality (default 9999; do not inflate without need)
  • property allowMissingRelations = "true"; — omit PCM relations not needed for constraints (mirroring every relation is not recommended)

Variables

Domains: discrete lists, ranges (int x = [1..9];), or combined. Types: boolean, date, double(n) / decimal(n), int, string, string[]. Use int for line quantity (not decimal).

Math: + - * / % ^, ceil(). String helpers: strlen, substr, strconcat, join, trim, strsplit, strcontain, strformat, regexpreplace, get(index, array), membership with in.

Annotations (examples): @(configurable=false, defaultValue=0.00), Peelable, tagName (line context), contextPath on extern for header fields.

@(contextPath="SalesTransaction.ShippingCountry") extern string ShippingCountry;
extern int MAX_VALUE = 9999;  // needs defaultValue if unmapped

Types & relationships

  • type Child : Parent { ... } — inheritance; variants not supported in constraint models
  • Bundle root must be in the model to constrain children; abstract bases need concrete products
  • virtual, groupBy, minInstanceQty / maxInstanceQty, split, sharingCount
  • Group types (PCM component groups): dot notation from root; parent(attr, 1) to reach past a group
  • Ramp: virtual container with groupBy=SalesTransactionItemGroup; groups do not support hide/disable/recommend action rules
  • relation name : Type[min..max] — tightest cardinality needed for performance

Constraints & rules

Variable status: User (manual), Default, Engine. Only exclude() may override User.

ConstructBehavior
constraint(expr, "msg", …)Hard rule; must resolve or error
message(expr, "msg", …, severity)Info / Warning / Error feedback; Error blocks task (not TLE save)
preference(expr, "msg")Soft nudge (Info only)
require(expr, relation[Type]{filters}==n, "msg")Forces presence/qty when true
setdefault(…)Like require but on condition change; use constraint() for unconditional hard revert
exclude(expr, relation[Type], "msg")Removes leaf type; can override User
rule(…, "hide"/"disable", …)UI hide/disable attribute, value, relation, or type
rule(…, "recommend", …)Suggestion; needs Run Config Rules Flow
table(…) / SalesforceTableCombination allow-list; object-backed rows need CRUD via Constraint Rules Engine Licenseless perm set

Proxy & aggregation

  • cardinality(Type[, relation]) vs count(expr)
  • parent(var[, level]) — ancestor values (read-only)
  • this.quantity — instance qty (calc rules; prefer cardinality() for structure)
  • relation.sum(attr), relation.count(expr), block aggregates with explicit domains
  • Assets: @(sourceContextNode="Asset", closerelation=true) relation … — read-only installed base
